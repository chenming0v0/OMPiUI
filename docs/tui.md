# 终端管理界面

OMPiUI 提供两套独立 TUI，共用全屏终端界面，但控制对象不同：

- **Server**：管理运行 Agent 的后端，查看健康检查、进程状态、网络配置和手机配对凭证。
- **Relay**：管理自建公网中转，查看在线隧道与转发连接、编辑路由、轮换接入密钥。

TUI 不启动编程会话，不修改 OMP 原生会话或 provider 配置。打开界面、切换页面和刷新状态不会自动启动后端或中转。

## 启动

在仓库根目录完成安装和构建：

```bash
npm install
npm run build
npm run tui:server
npm run tui:relay -- --config /path/to/relay.config.json
```

也可以直接运行构建产物：

```bash
node packages/admin/dist/cli.js tui
node packages/relay/dist/cli.js tui --config /path/to/relay.config.json
```

必须使用交互式终端；SSH 使用 `ssh -t`，容器使用 `docker exec -it`。非交互脚本继续使用管理器的 `start`、`stop`、`restart`、`status`，以及中转的 `init`、`start` 命令。

## 页面与操作

界面适配宽、窄终端，最小尺寸为 48 列、16 行。宽终端显示像素字标和编号分页，概览同屏展示近期动态；窄终端使用紧凑分页。支持中文与长地址，输入视窗跟随光标滚动，选中行后按 `i` 查看完整值。

| 输入                            | 操作                                     |
| ------------------------------- | ---------------------------------------- |
| `Tab` / `Shift+Tab`、左右方向键 | 切换页面                                 |
| 上下方向键、`j` / `k`           | 选择行或滚动日志                         |
| `/`、`Ctrl+P`、回车             | 打开当前页面的命令面板                   |
| 空格                            | 刷新并清除操作提示                       |
| `s` / `x` / `r`                 | 启动 / 停止 / 重启                       |
| `e`                             | 编辑当前页面配置                         |
| `v`                             | 在凭证页显示或隐藏凭证                   |
| `q` / `Ctrl+C`                  | 退出；正在管理本地服务时先确认           |
| `Esc`                           | 关闭命令面板、取消表单或确认             |
| `Ctrl+S`                        | 保存表单；回车依次编辑各项，最后一项提交 |

表单中支持左右方向键移动光标，`Ctrl+A` / `Ctrl+E` 跳到开头 / 结尾，`Ctrl+U` 删除光标前的内容。

中转隧道页另有：`a` 添加、`e` 编辑、`d` 断开、`w` 轮换密钥、`z` 删除。停止、重启、断开、轮换和删除都需要确认，默认选中取消。

凭证默认遮蔽，主动显示后 30 秒自动隐藏；切换页面也会隐藏。日志最多保留 300 行，并移除终端控制序列、URL 访问令牌和已知密钥。

## 后端管理器

未运行管理器时，TUI 在配置的管理端口提供原有管理 API。启动的后端输出进入日志页，不会打乱全屏界面。退出确认后停止自己启动的后端并关闭管理 API，避免留下无主进程。

如果管理端口已被现有 OMPiUI 管理器使用，TUI 用独立管理令牌验证后接入它。适用于 systemd、Docker 或已经运行的管理 Web UI：

- 仍可以通过原管理器启动、停止、重启后端和保存配置。
- 退出 TUI 不会停止原管理器或它的后端。
- 日志页只显示本次 TUI 的操作记录，后端完整输出仍在原管理器的终端、journald 或容器日志中。
- 错误令牌或非管理器服务不会被静默接管。

配置中的监听地址、端口和健康检查地址应保持一致。健康检查地址用于连接后端；监听 `0.0.0.0` 时通常用 `http://127.0.0.1:<端口>` 检查。中转密钥输入留空会保留原密钥；清空中转地址可关闭隧道。保存不会自动重启正在运行的后端。

## 中转管理器

没有配置文件时，可以在 TUI 中创建第一条隧道。配置存在但格式错误时，启动会报出错误；先修复文件再进入 TUI。

TUI 只控制在本次界面内启动的中转，不接管已经独立运行的 `omp-relay start`。监听端口被占用时会报错，不会终止其他进程。

- 添加、编辑、删除隧道和修改监听/TLS/公网配置，只修改配置文件；重启中转后生效。
- 轮换密钥后旧密钥在当前运行实例中仍有效，重启后才失效；需要把新密钥同步到对应电脑。
- 断开在线隧道会中断当前转发，但电脑仍可自动重连；撤销权限应轮换密钥或删除隧道配置后重启。
- 配置文件在外部修改后，保存会拒绝覆盖；先执行重新读取配置，再编辑。
- 必须保留至少一条隧道。配置文件以仅所有者可读写的权限保存。

退出确认后停止本次 TUI 启动的中转。需要长期无人值守运行时，使用现有 `omp-relay start` 配合 systemd 或容器，而不是依赖 SSH 终端一直在线。

## 验证

```bash
npm run test -w @ompiui/tui
npm run test -w @ompiui/admin
npm run test -w @ompiui/relay
```

实际 PTY 和截图验收需要安装 Playwright 及 Chromium，并先构建 `tui`、`relay`、`admin`、`protocol`、`omp-worker`、`server`：

```bash
node scripts/verify-tui.mjs
```

脚本使用临时数据目录和随机本机端口，以 mock 后端验证启停、表单、脱敏、退出清理和 120/80/48 列布局，输出真实终端截图到 `artifacts/tui`。可通过 `OMPIUI_PLAYWRIGHT_MODULE_DIR` 指向已有 Playwright 所在模块目录；已有 Edge 时可设 `OMPIUI_TUI_BROWSER_CHANNEL=msedge`，不必另外下载 Chromium。
