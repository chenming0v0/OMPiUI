# 第二轮网络审计复核

上一轮 #84 至 #91 的修复已作为原子提交 `ceb73b4` 保存。本轮针对
#92 至 #107 按实际调用链复核，不把静态推测直接当作故障。

| Issue | 核对结论 | 处理 |
| --- | --- | --- |
| #92 | 字节账本失真不成立：`resetEpoch` 同时清空 history、sizes 并抵减 bytes；被淘汰对象不会再参与 shift。全局按冷流回收是现行策略，不是重复抵减 | 保留现行逻辑 |
| #93 | 不成立：sequence 只在 publish 时递增；当前游标即使 history 为空也不 resync，旧游标意味着确有发布过但已淘汰的事件 | 保留正确的过期判断 |
| #94 | “首屏没有字节预算”不成立，上一轮已在候选页上检查 maxBytes；独立分页参数上限需要补齐 | 协议限制 200 条 / 4 MiB，worker 分页亦封顶 |
| #95 | 磁盘 reader 不复用不成立，已有按文件缓存的 reader 和条目引用；但 preview 命令路由确实丢弃同步参数 | 补齐 worker 命令表及 attached preview 的 syncCursor/beforeId |
| #96 | 无消费方广播的流量风险被夸大：当前 packages.manage 未接通进度回调；store 按 commandId 长期累积的问题成立 | 进度快照只保留最近 32 条，不移除协议通道 |
| #97 | 成立，控制帧使用字符限长 | relay 复用原始 Buffer，解码前按字节限长 |
| #98 | 成立，与 #97 部分重复；TunnelClient 未设置入站帧上限 | 显式 maxPayload，文本与二进制分别按协议限制 |
| #99 | 终端 scrollback 单位错配成立，pending 已按字节；stdout 不是“错误字节记账”，而是缺少单行上限 | scrollback 按 UTF-8 字节限制，游标保持字符偏移；stdout 单行 1 MiB、积压 8 MiB，超长行报错后跳过并恢复解析 |
| #100 | 不成立：控制器在 await 前已注册，切换服务器先 abort 再 clear；await 返回后代次检查阻止 fetch，clear 集合不会撤销 abort | 不修改正确的取消逻辑 |
| #101 | 附件没有前置容量限制、队列删除重传剩余图片成立；“附件转换长期保存两份等长字符串”不符合函数返回值 | 单附件 5 MiB、总量 16 MiB，命令发送前检查 24 MiB；新增 worker 原子移除队列命令，前端不再重建队列 |
| #102 | 不成立：预览默认关闭且计算前已有 canPreview；对象浅拷贝只复制字符串引用，不复制 4 KiB 正文。就地修改会破坏外部 store 快照语义 | 保留不可变快照和既有 500ms 通知合并 |
| #103 | 已读历史累计及离开后驻留成立；活动 pane 主动向前阅读不是无意义重复下载，不应为节省内存静默丢掉正在读的历史 | 离开时释放超过 100 条或 8 MiB 的历史；活动 pane 保留已读范围，未新增双向窗口分页 |
| #104 | 跨会话 branch 常驻成立；timeline 不是第二份完整 base64，但强引用延长原历史生命周期 | 最多缓存 4 个非活动会话，活动 pane 不被淘汰；timeline 改为按 items 数组的 WeakMap |
| #105 | attached preview 漏传同步参数及参数无上限成立，与 #94/#95 同源；首屏字节预算不存在的描述不成立 | 补齐两条 preview 路由并校验参数 |
| #106 | 成立：重展开从零回填、取消信号缺失、累计没有预算 | 缓存 nextByte 与未完成 JSONL 行，跨 pane 合并请求；最后一个消费者取消即中止。单轮最多 8 MiB / 64 页，缓存最多 4 份，每份消息正文 8 MiB / 2000 条；超限显示部分转录并可继续读取 |
| #107 | 存活 worker 超时重放和客户端嵌套重试成立；“HTTP 503 自动重试”和“supervisor 无次数上限”不成立，HTTP 只重试 GET/HEAD 网络异常，supervisor 原来至多重试一次 | 仅旧 worker 已失效时允许重发；WORKER_RESULT_UNKNOWN 不自动重试；preview 重试只保留一层，并清理退避取消监听器 |

## 范围

不改变官方会话目录，不为浏览或刷新创建写入 runtime，不重启生产会话。
活动会话的任意深度阅读仍保留已读数据；双向滑动窗口属于后续性能改造，
本轮没有通过截断活动历史来声称完成这项能力。
